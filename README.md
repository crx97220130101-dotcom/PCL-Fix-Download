## 功能与限制

- 单文件 EXE，内置 dnlib 和其许可证，不需要 Python 或外置 DLL。
- 拖入一个原版 EXE，或双击工具后在对话框选择文件。
- 严格检查 SHA256，只接受下表列出的两个原始构建；改文件名不影响匹配。
- 在原文件旁生成 `.fixed.exe`，保留原文件；同名时自动编号。
- 先写临时副本，静态验证通过后才发布结果；失败时尝试清理临时文件。
- 不自动启动目标程序，不执行游戏或整合包下载，不要求管理员权限，不主动联网。
- 存在未完整测试的重建 IL 路径；使用前请自行审查源码并做好配置备份。

本仓库只包含补丁工具源码和 dnlib 依赖，**不包含原版 PCL、修改版 PCL 或 Minecraft 二进制**。工具不是完整 PCL 工程的重新编译产物，也不保证与把源码常量改为 `False` 后重建完全等价。

## 使用

1. 从本仓库源码构建单文件工具，或使用发布者提供的对应 Release。
2. 将原版 PCL EXE 拖到 `PCL-Repair-Standalone.exe` 上；也可以直接双击工具选择文件。
3. 成功后，在输入文件所在目录运行新生成的 `原文件名.fixed.exe`。
4. 如需回退，继续运行保留的原版 EXE。

原文件不被覆盖，但原版和修改版可能使用同一套用户配置。输入文件所在目录必须可写。工具一次只处理一个文件，不会自动适配未知版本。

命令行用法：

```powershell
.\bin\PCL-Repair-Standalone.exe "C:\Games\PCL\Plain Craft Launcher 2.exe"
```

辅助命令：

```powershell
# 查看内置 dnlib 许可证
.\bin\PCL-Repair-Standalone.exe --license

# 仅检查内置依赖能否加载，不修改目标文件
.\bin\PCL-Repair-Standalone.exe --package-check
```

默认在处理完后等待回车，便于查看结果。自动化调用可设置 `$env:PCL_REPAIR_NOPAUSE = '1'`。

## 本地构建

### 环境

- Windows，安装 .NET Framework 4.x，包含系统 C# 编译器。
- Windows PowerShell 5.1，或可运行此构建脚本的 PowerShell。
- 不需要 Python、.NET SDK、NuGet 恢复或联网下载依赖。

双击仓库根目录的 `build.bat`，或执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

`Bypass` 只用于此 PowerShell 进程，不会修改系统永久执行策略；也可按照自己的执行策略直接运行脚本。

输出：`bin/PCL-Repair-Standalone.exe`。

构建脚本使用脚本所在目录解析路径，不依赖开发者机器上的盘符或用户名。编译时将 `lib/dnlib.dll` 和许可证嵌入资源，运行时在内存中加载依赖；不把 DLL 解压到目标目录。构建本身不会启动补丁器或修改任何 PCL 文件。

### 为什么不只改一个字节

`RestrictMcDownload` 是 VB 编译期常量。原始构建中的部分正常路径已被编译器删除；仅修改常量元数据不会恢复这些路径。另外，原常量的元数据 blob 被其他常量共享，直接修改共享数据可能波及无关功能。

本工具为目标字段创建独立的 `False` 常量，并处理以下路径：Minecraft 版本列表加载、Minecraft 修改卡片显示、手动整合包选择入口、整合包类型安装分派、整合包资源的安装/保存操作、拖拽安装错误处理中的限制分支。恢复的手动选择器没有复刻上游的文件扩展名过滤，分派也未复刻所有诊断日志。

### 静态验证边界

自动验证要求六个原有方法改变、只新增一个委托适配方法、只有目标字段常量变化，检查托管资源内容、程序集标识、入口点、关键加载器及整合包调用。它不是完整 CLR 验证器，不检查所有运行时路径，也不能代替 GUI、JIT、网络或真实安装测试。

## 退出码

| 退出码 | 含义 |
|---|---|
| `0` | 修复与静态验证成功，或辅助命令成功 |
